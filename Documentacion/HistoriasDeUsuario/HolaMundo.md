[ARQUITECTURA] Plan de Despliegue: "Hola Mundo" con Ansible y AnsistranoPara materializar este objetivo en el Nodo de Desarrollo Headless (PC 11 @ 10.0.10.11), aplicaremos un enfoque de infraestructura inmutable. Al aprovechar el canal seguro SSH ya habilitado en el puerto 22 de este nodo, Ansible actuará como orquestador y Ansistrano proveerá la arquitectura de despliegue profesional (ciclo de releases y enlaces simbólicos) sin fricciones.   1. Definición de la Infraestructura BaseDestino Operativo: Nodo PC 11 (10.0.10.11).   Aislamiento (Contenedor): Un servidor web ultra-ligero (Nginx) encapsulado en Docker, que servirá un archivo estático index.html con el saludo. Todo gobernado por un docker-compose.yml.Orquestación Continua: Ansible ejecutará la conexión remota, mientras que Ansistrano gestionará el ciclo de vida del código (clonación, enlace simbólico a la versión en producción, y retención de versiones anteriores para rollbacks instantáneos).2. Estructura del Repositorio (El Yunque)El proyecto requerirá un repositorio unificado que contenga tanto el código de la aplicación como el código de la infraestructura (IaaC). La arquitectura de carpetas será:src/ (La Aplicación)index.html: El "Hola Mundo".Dockerfile y docker-compose.yml: Instrucciones para levantar Nginx mapeando el puerto adecuado.ansible/ (La Forja)inventory.ini: Fichero que declara al PC 11 como objetivo.deploy.yml: El playbook maestro que invoca los roles de Ansistrano.hooks/: Directorio para las tareas específicas de transición (ej. recargar Docker al cambiar de versión).3. Fases de EjecuciónFase 1: Preparación del Controlador (Entorno Local)Verificar la instalación local de Ansible.Instalar la suite de Ansistrano mediante Ansible Galaxy: ansible-galaxy install ansistrano.deploy ansistrano.rollback.Confirmar que tu clave SSH pública está inyectada en el PC 11 para permitir un despliegue desatendido y sin contraseñas.Fase 2: Configuración del Motor de DespliegueDiseñaremos el playbook (deploy.yml) definiendo las variables clave de Ansistrano:ansistrano_deploy_to: Ruta base en el PC 11 (ej. /opt/holamundo).ansistrano_deploy_via: rsync (ideal si no quieres obligar al PC 11 a clonar de un repositorio externo, copiando directamente tu código local) o git.ansistrano_keep_releases: 3 (mantendrá las 3 últimas versiones desplegadas para revertir en caso de colapso).Punto de Inserción Crítico: Definiremos un hook en la variable ansistrano_after_symlink_tasks_file. Este archivo de tareas ejecutará la recarga del contenedor (docker compose down && docker compose up -d --build) justo después de que Ansistrano actualice el enlace simbólico current hacia la nueva versión.Fase 3: Fricción de Acero (Ejecución)Lanzaremos la directriz de despliegue: ansible-playbook -i ansible/inventory.ini ansible/deploy.yml.Ansistrano creará automáticamente la estructura de directorios (releases, shared), transferirá el código, actualizará el symlink a la fecha actual y orquestará a Docker para que sirva la aplicación.Fase 4: Validación de CircuitoComprobaremos empíricamente el acceso al contenedor atacando la IP del PC 11 en el puerto expuesto para certificar la entrega del "Hola Mundo".
