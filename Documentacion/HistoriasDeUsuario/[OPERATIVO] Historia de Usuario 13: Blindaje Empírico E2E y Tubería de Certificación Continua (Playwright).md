Se trasciende la dependencia de pruebas manuales para anclar un sistema autónomo que audita la interfaz de usuario, intercepta el consumo innecesario de tokens del orquestador LLM y bloquea despliegues defectuosos hacia producción de forma determinista.1. Descripción GeneralComo Ingeniero de Software (Vértice Biológico) y Custodio de la Arquitectura,Quiero instanciar Playwright como el motor canónico de pruebas End-to-End (E2E), integrado directamente en la tubería de Integración Continua (CI) y regido por normas de crecimiento simbiótico,Para garantizar que ninguna funcionalidad crítica (orquestación del Lienzo Híbrido, Escudo Anti-Trampas, rutas protegidas del middleware) colapse por regresiones ocultas, bloqueando atómicamente el paso del código al Nodo 11 si el sistema no supera la auditoría empírica automatizada.2. Ejes Arquitectónicos del Blindaje EmpíricoEl despliegue de este arnés no es la mera instalación de una librería; es la forja de un centinela perimetral que vigila el estado de la aplicación desde la perspectiva del usuario final, operando bajo las siguientes directrices operativas:A. El Cortafuegos del Oráculo (Mocking Determinista)Para garantizar la inmunidad ante fallos de red externos y evitar el consumo estéril de tokens durante el ciclo de integración continua, el motor E2E tiene prohibido despertar a Gemini. Las llamadas a la ruta /api/triage y los endpoints del LLM serán interceptadas quirúrgicamente (page.route()), inyectando matrices JSON pre-calculadas (Ruta Base vs. Ruta S+ Grade) que aseguren una latencia constante y un entorno de prueba 100% determinista.B. Pacto de Crecimiento Simbiótico (Cobertura Incremental)El ecosistema de pruebas no es un bloque estático; es un organismo que debe expandirse en paralelo al código. Se instaura la norma de que toda nueva entidad funcional (Caso de Uso, Componente UI complejo o Endpoint) debe ir escoltada por su respectivo espectro de validación E2E. Un Pull Request carente de cobertura empírica será rechazado por el linter arquitectónico.C. La Aduana de Despliegue (Bloqueo Atómico IaaC)Playwright se incrusta como la última y más severa aduana en el flujo CI/CD (.github/workflows/ci.yml). El script audit-anchor.sh no emitirá el código de salida exitoso (0) hasta que la suite E2E confirme la viabilidad del flujo crítico. Si la prueba falla, el playbook de Ansible (deploy.yml) hacia el Nodo 11 quedará fulminantemente abortado, protegiendo la versión de producción actual (Táctica del Refugio).3. Normativas de Desarrollo y Forja (El Yunque de Pruebas)Topología Aislada: Todos los artefactos E2E residirán confinados en el directorio raíz tests/e2e/, manteniendo una simetría topológica con el directorio src/features/ para facilitar la trazabilidad.Selectores Resilientes: Queda proscrito localizar elementos del DOM mediante clases CSS (.bg-zinc-900) o jerarquías frágiles (div > span). Las interacciones se anclarán de manera obligatoria a atributos de accesibilidad (aria-label, role) o atributos de prueba específicos (data-testid="hybrid-canvas-node"), garantizando que las mutaciones de estilo de Tailwind no fracturen las pruebas.Gestión del Estado Híbrido: Las pruebas deben contemplar los retardos asíncronos propios del renderizado reactivo, utilizando aserciones que esperen a la resolución del DOM (await expect(locator).toBeVisible()) en lugar de pausas temporales fijas (page.waitForTimeout), cumpliendo el Filtro C de economía termodinámica.4. Criterios de Aceptación (Verificación Empírica)Escenario 1: Orquestación Determinista y Desacople del LLMDado la ejecución de la suite de pruebas E2E sobre el entorno local o CI.Cuando el agente automatizado simula la solicitud de generación de un itinerario.Entonces el motor Playwright intercepta la llamada a /api/triage, anula la petición de red externa y devuelve un TacticalMetadataSchema mockeado en menos de 50 ms.Y la interfaz renderiza el HybridCanvas de forma exitosa basándose en el mock, validando la coreografía sin consumir tokens.Escenario 2: Validación Visual de Saturación Térmica (S+ Grade)Dado la inyección de un contexto de usuario completo (tiempo, presupuesto, restricciones) que simula el 100% de saturación.Cuando el itinerario se proyecta en la interfaz.Entonces la aserción automatizada busca y localiza afirmativamente en el DOM el atributo data-testid="anti-trap-shield-warning".Y confirma la presencia y clickabilidad del enlace de afiliación preventiva (CPA) en los nodos de alta fricción.Escenario 3: Resiliencia del Centinela Perimetral (/Admin)Dado un intento de acceso directo mediante page.goto('/Admin/System') sin inyectar cabeceras de autorización.Cuando el Edge Middleware procesa la petición.Entonces Playwright valida que la respuesta de red es un estado HTTP 401 (Unauthorized) o la redirección 308 forzada hacia HTTPS.Y corrobora que la tabla de telemetría (DataTable) no es accesible ni expone el DOM restringido.Escenario 4: Bloqueo de Despliegue en Falla Empírica (CI/CD)Dado la inyección intencionada de un error de renderizado en un componente crítico (ej. ocultar el botón de generación de ruta).Cuando se dispara la acción de GitHub para integrar el código hacia la rama main.Entonces el paso de ejecución npx playwright test colapsa arrojando un error.Y el workflow detiene su ejecución inmediatamente, impidiendo la activación de ansible-playbook hacia el Nodo 11, garantizando el Zero Downtime y la inmutabilidad de la producción sana.
