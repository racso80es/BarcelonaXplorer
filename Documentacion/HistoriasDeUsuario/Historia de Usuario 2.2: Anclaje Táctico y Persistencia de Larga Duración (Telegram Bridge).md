Historia de Usuario 2.2: Anclaje Táctico y Persistencia de Larga Duración (Telegram Bridge)Estatus: Refinado / Listo para ImplementaciónMódulo: Integración B2C y Persistencia Relacional Híbrida1. Descripción GeneralComo explorador recurrente que ha completado un itinerario S+ Grade,Quiero poder vincular mi progreso actual a un canal de comunicación asíncrono (como Telegram) mediante un solo clic,Para salvaguardar mi ruta ante la pérdida de cookies, acceder a ella desde cualquier otro dispositivo y recibir alertas tácticas (clima, aforos, enlaces CPA) directamente en mi teléfono.2. Justificación Arquitectónica (Táctica del Refugio)Delegar la persistencia de largo plazo a una plataforma externa (Telegram) elimina el desgaste operativo de gestionar correos, recuperación de contraseñas y envío de correos transaccionales (SMTP). La base de datos MySQL estática del Nodo 11 se utilizará para enlazar la Identidad Sombra efímera con un ID físico de hardware (el chat_id de Telegram), consolidando un ecosistema omnicanal.   3. Coreografía de la Conversión VoluntariaEl Drop de Gamificación: Solo cuando el usuario alcanza una densidad de prompt alta (100%) y genera una ruta definitiva, el componente de UI muestra un botón de acción táctica (ej. "Asegurar Ruta y Recibir Alertas").Enlace Profundo (Deep Link): El botón ejecuta una redirección a Telegram inyectando el identificador local como parámetro de inicio: t.me/BXplorerBot?start=<bx_session_id>.Consolidación Relacional: El webhook del servidor, construido sobre el App Router de Next.js, recibe el evento de inicio del bot, extrae el chat_id seguro del usuario y el parámetro start (UUID). El ORM Prisma registra esta tupla en el volumen persistente de MySQL.   4. Criterios de Aceptación (Verificación Empírica)Escenario 1: Ejecución del Anclaje TácticoDado un usuario con la ruta generada que pulsa el botón de asegurar ruta.Cuando la aplicación cliente abre la URI de Telegram con el parámetro de inicio.Entonces el usuario visualiza el bot de BarcelonaXplorer y pulsa "Iniciar".Escenario 2: Consolidación en la Forja RelacionalDado el evento entrante desde la API de Telegram hacia el webhook de Next.js.Cuando el servidor procesa el chat_id del usuario y el UUID inyectado en el payload.Entonces Prisma inserta o actualiza el registro en la base de datos MySQL, vinculando ambas identidades.   Y el bot responde confirmando el anclaje: "Identidad asegurada. Aquí tienes tu itinerario S+ Grade guardado en firme."Escenario 3: Recuperación Omnicanal (Cross-Device)Dado un usuario anclado que abre la PWA de BarcelonaXplorer en un ordenador de sobremesa nuevo (sin cookies previas).Cuando solicita al bot de Telegram un enlace de acceso mágico o pulsa un botón inline.Entonces el sistema le provee una URL temporal firmada que, al ser abierta en el ordenador, inyecta su UUID original en las cookies del nuevo navegador.
