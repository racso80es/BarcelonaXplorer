Historia de Usuario 3: Persistencia Vectorial Embebida y Aislamiento IaaC (LanceDB)Estatus: Refinado / Listo para ImplementaciónMódulo: Infraestructura, Persistencia Vectorial y Tubería IaaC1. Descripción GeneralComo Operador Técnico y Arquitecto de Software del Nodo 11,Quiero instanciar la base de datos vectorial (LanceDB) como un motor embebido dentro del proceso de Next.js y persistir sus índices a través de un mapeo de volumen local (Bind Mount) en el servidor de producción,Para garantizar una latencia de red cero en el cruce de vectores (RAG), evitar la sobrecarga térmica de administrar contenedores paralelos y asegurar que el historial conversacional de los usuarios sobreviva a los ciclos de despliegue automatizados.2. Justificación Arquitectónica (Vía del Yunque)Bajo el patrón BFF (Backend For Frontend) y la disciplina de Código Único de BarcelonaXplorer, se rechaza la fragmentación prematura en microservicios. Desplegar un contenedor paralelo exclusivo para tareas vectoriales añade latencia HTTP interna y complejidad en la orquestación. LanceDB, al operar directamente sobre Apache Arrow en el mismo hilo de Node.js, erradica esa latencia.
Además, dado que el sistema se despliega mediante Ansistrano (que altera los enlaces simbólicos y recarga los contenedores con docker compose down && docker compose up -d), la memoria vectorial debe externalizarse al sistema anfitrión para evitar amnesia masiva en cada actualización.   3. Coreografía de Infraestructura y DespliegueForja Embebida: LanceDB se integra como una dependencia estándar en el package.json de Next.js, operando puramente como una librería en la capa de infraestructura del monolito.   Volumen de Inmunidad (Táctica del Refugio): Se forja un volumen local en el sistema anfitrión del Nodo 11 (ej. /home/racso/Despliegues/BarcelonaXplorer/lancedb_data), replicando exactamente la misma estrategia de aislamiento utilizada para el contenedor estático de MySQL.   Declaración en Docker Compose: El manifiesto docker-compose.yml mapeará este directorio físico directamente a la ruta interna de almacenamiento del contenedor Next.js (ej. /app/vector_storage).Independencia de la Tubería IaaC: Cuando Ansible ejecute un nuevo pase a producción, el enlace simbólico current apuntará a la nueva versión del código, pero el motor embebido de la nueva compilación retomará la lectura de la carpeta inmutable en el disco, manteniendo intacta la memoria de todos los identificadores sombra (UUIDs).   4. Criterios de Aceptación (Verificación Empírica)Escenario 1: Eficiencia de Orquestación (Cero Contenedores Paralelos)Dado el despliegue del proyecto BarcelonaXplorer en el Nodo 11.Cuando el operador ejecuta docker ps para auditar la topología.Entonces el sistema muestra únicamente dos contenedores activos: el monolito de Next.js PWA y el motor estático MySQL.   Y las operaciones de lectura/escritura vectorial se ejecutan sin llamadas a puertos de red externos.Escenario 2: Persistencia Inmutable frente a Ciclos de DespliegueDado un conjunto de itinerarios hiper-personalizados y contextos de usuarios ya vectorizados en disco.Cuando el operador dispara el playbook deploy.yml de Ansistrano para desplegar una nueva versión del código.   Entonces el hook after_symlink.yml purga y levanta el contenedor de Next.js.   Y al arrancar, el nuevo contenedor reconoce de forma inmediata los vectores preexistentes en el volumen /app/vector_storage, garantizando la continuidad cognitiva para todos los usuarios activos.Escenario 3: Tolerancia Cero a la Pérdida por Caída de ContenedorDado el entorno de producción operando bajo estrés termodinámico.Cuando el proceso de Docker Compose colapsa o el servidor sufre un reinicio abrupto.Entonces la estructura de datos binaria de LanceDB sobrevive íntegra en el sistema anfitrión del Nodo 11, sin corrupción estructural, lista para el rearme automático.
