[ARQUITECTURA] Base Fundacional del Proyecto BarcelonaXplorer v1.0

Matriz de Indexación Tridimensional:
Naturaleza: Plan Maestro, Arquitectura de Negocio y Ecosistema de Software.
Entorno: Proyecto BarcelonaXplorer (PWA + IA Orquestadora).
Entropía Asimilada: Destilación del modelo de ingresos pasivos. Superación de la saturación de guías turísticas estáticas mediante la orquestación dinámica y la inyección transparente de afiliación en rutas hiper-personalizadas.

1. Visión Estratégica: El Conserje Efímero
BarcelonaXplorer no es un buscador estático ni un directorio de listados clónicos ("Top 10 cosas que hacer"). Se define como un Orquestador de Experiencias impulsado por IA, diseñado para eliminar la fricción de decisión del turista.

Fricción Cero (Input): El usuario interactúa exclusivamente con un prompt en lenguaje natural declarando su contexto exacto (tiempo disponible, presupuesto, compañía, ubicación actual y preferencias).

Valor Único (Output): El sistema no devuelve opciones aisladas, sino un itinerario milimétrico, cronológico y ejecutable, cruzado en tiempo real con variables externas (horarios de cierre, clima, distancia).

2. Vía del Yunque: Arquitectura de Código Único
Para maximizar el retorno de inversión y anular el desgaste de mantenimiento que supone programar para múltiples plataformas (iOS, Android, Web), el proyecto asume un enfoque estricto de código único.

Núcleo Front-End: Next.js (App Router) con TypeScript y Tailwind CSS. Garantiza el Server-Side Rendering (SSR) vital para la indexación orgánica (SEO) de las URL.

Despliegue Multiplataforma (PWA): La web operará como una Aplicación Web Progresiva. Mediante Service Workers y un manifiesto, los usuarios podrán instalarla nativamente en cualquier dispositivo, esquivando las comisiones y los lentos procesos de validación de las App Stores de Apple y Google.

Memoria Cognitiva: LanceDB (Base de datos vectorial) almacenará el contexto de la ciudad (nodos de interés) vectorizados por atributos (romántico, lluvioso, cultural), permitiendo al agente de IA cruzar intenciones complejas con precisión quirúrgica.

Infraestructura de Despliegue: Tubería IaaC automatizada mediante Ansible y Ansistrano hacia el Nodo 11 (10.0.10.11), encapsulando la aplicación en contenedores Docker servidos a través de un proxy inverso Nginx.

3. Vía del Fuego: Ingeniería de Ingresos Pasivos
La viabilidad del proyecto reside en monetizar el tráfico de manera desatendida. No hay gestión de inventario, ni pasarelas de pago propias, ni atención al cliente.

Integración CPA/CPS (Coste por Acción/Venta): La IA inyecta de forma natural y transparente enlaces de afiliados dentro del propio itinerario generado.

Gastronomía: Botones de reserva enlazados a la API de TheFork.

Cultura y Ocio: Entradas a monumentos o tours a través de Civitatis, Tiqets o GetYourGuide.

Movilidad: Sugerencias de transporte entre puntos con referidos de Cabify o FreeNow.

Evolución B2B (Fase 2): Arbitraje de atención. Negocios locales (SaaS) pagarán suscripciones automatizadas para alterar el peso de su vector en LanceDB, aumentando la probabilidad de ser incluidos en las rutas generadas por la IA si encajan con el perfil del usuario, respetando siempre el Filtro de pertinencia.

4. Trazabilidad y Desarrollo Kaizen
El proyecto crecerá de forma modular:

Fase Alpha: Sustitución del "Hola Mundo" por el esqueleto base de Next.js PWA en el contenedor Docker.

Fase Beta: Diseño de la base de datos vectorial e integración del motor LLM para procesar prompts y devolver rutas en formato JSON estructurado.

Fase Gamma: Parseo del JSON a interfaz visual (Tailwind) e inyección de los algoritmos de afiliación para el arranque de la monetización.
